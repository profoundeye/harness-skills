# 轻量 Harness 规则

创建 Sprint Harness 记录时，优先遵守这些规则：

- `AGENTS.md` 只做一个 Agent 入口，说明如何理解项目、如何修改、如何验证、如何交付。
- 使用短追踪链：`REQ -> TASK -> VERIFY -> COMMIT`。
- 每个任务都要保持小而聚焦，并包含目标、范围、验证方式和完成标准。
- 验证证据是完成任务的必要条件。证据可以是命令、测试名、截图、CI 链接或人工检查结果。
- 先运行最小相关验证；只有在风险和影响范围需要时，才扩大到更全面的检查。
- 用简单健康检查发现重复 ID、孤立需求、没有需求来源的任务、没有验证的验收标准。
- 技能要小，像操作手册一样按需触发。不要引入完整 Jira/Scrum 仪式、故事点、重型合规 RTM，或默认多 Agent DAG 编排。
